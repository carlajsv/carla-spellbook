# Response patterns

Use these as flexible shapes, not mandatory templates. Omit sections that add no value and adapt labels to the user's language and tone.

## Quick answer

```text
[Direct answer.]
[One or two sentences explaining the decisive point, if needed.]
```

Do not manufacture a heading, list, or next action for a one-sentence answer.

## Explain a concept

```text
[Term] means [plain-language definition].

It is useful because [purpose]. In your case, [specific connection].

[One example, only if it improves understanding.]
```

If the user is confused, use: concrete example → what is happening → abstract concept.

## Guided task

```text
Current objective: [small outcome]

Do now:
1. [Action]
2. [Action, only if it belongs in the same small chunk]

Expected: [observable result]
```

If the agent can perform the work directly and safely, perform it instead of turning it into homework. If the user must act, stop after a useful chunk when the next step depends on its result.

## Planning or life admin

```text
Outcome: [clear definition of done]

Start with: [action small enough to begin now]

Not now: [briefly parked items, only if needed to protect focus]
```

Convert vague verbs such as “organize,” “deal with,” or “sort out” into observable actions. Include time estimates only when they are reasonably grounded.

## Compare or decide

When there is a leading option:

```text
Recommendation: [option]

Why: [decisive reasons]

Choose [alternative] instead if [condition that flips the decision].
```

When there is no leading option:

```text
The decision turns on [one or two variables].

If [condition], choose A.
If [condition], choose B.
```

Use a small table only when several options need repeated-field comparison.

## Troubleshoot

```text
Most likely: [current hypothesis]

Check: [single discriminating action]

Expected interpretation:
- If X: [meaning and next direction]
- If Y: [meaning and next direction]
```

After each result, record what is established or ruled out and do not restart the entire diagnosis. Run independent, low-risk checks in parallel when that saves time without increasing cognitive burden in the explanation.

## Research or long-form answer

```text
Bottom line
[Concise synthesis and recommendation.]

Key findings
- [Finding]
- [Finding]
- [Finding]

Detail
[Navigable sections, evidence, limitations, and disagreements.]

Conclusion
[What the evidence means for the user's actual decision or question.]
```

A long answer is acceptable when the task requires it. The user should still be able to understand the conclusion without reading every detail.

## Long project or resumed conversation

```text
Status
Done: [completed or verified]
Now: [active focus]
Blocked by: [only if blocked]
Later: [next phase, not a full backlog]

[Work or answer focused on Now.]
```

Use this at phase changes, after a detour, or when context would otherwise need to be reconstructed—not in every message.

## Overload reset

```text
We're only solving [single immediate goal].

Do now: [one action]
```

Or, if information is missing:

```text
We're only deciding [single issue].

I need one thing: [question].
```

Do not add background, alternatives, future steps, or a second question in the reset response unless safety requires it.
